## 1. health.go 为什么嵌入 v1.UnimplementedHealthServiceServer?
proto 生成的 grpc 接口(HealthServiceServer)要求实现 mustEmbedUnimplementedHealthServiceServer() 这个私有方法,只有嵌入 UnimplementedHealthServiceServer
才能满足。而 HTTP 接口只要有一个 Check 方法就行。所以一个结构体同时满足 grpc + http 两个接口,这就是"一个实现,双协议注册"。

## 2. http.go / grpc.go 的职责分工:
- 接收 *Server 配置(从 yaml 来)→ 拼成 kratos 的 ServerOption(地址、超时、中间件)
- 创建传输层 server → 调用 v1.RegisterHealthServiceHTTPServer(srv, health) 注册路由
- health 参数是从外面注入的,不是自己 new 的 —— 这就是依赖注入,wire 负责"从哪拿 health"

## 3. provider.go 是 wire 的入口
- ProviderSet 里列了 3 个构造函数,wire 会按"参数类型"自动匹配装配。


## 4.wire的工作流
1. //go:build wireinject 是"魔法开关":普通 go build / go test 时,这行 tag 不满足,整个 wire.go 被编译器跳过,编译用的是 wire 生成的 wire_gen.go。而 wire
   工具运行时,会带上这个 tag 编译你的包,看到 wire.Build(...) 就分析依赖关系。所以:wire.go 只在 wire 工具眼里存在,普通编译永远看不到它。
2. panic(wire.Build(...)) 永远不会真的执行 —— 它只是给 wire 看的"装配清单"。wire 扫描到它,在内存里把图建出来,生成 wire_gen.go(真正的实现),然后 panic
   这一行在生成代码里被替换掉了。wire_gen.go 里才是真的 func wireApp(...) (*kratos.App, func(), error) { ... }。
3. wire 怎么知道谁给谁?看"类型":
   - wireApp 的入参(*server.Server, log.Logger)是免费提供的"原料"
   - server.ProviderSet 里 3 个构造函数按类型匹配:
    - NewHealthService() 无参 → 直接产出 *HealthService
    - NewHTTPServer(c *Server, health *HealthService, logger log.Logger) → 三个入参都能从"原料"和"上面的产出"里找到 → 产出 *http.Server
    - 同理 NewGRPCServer → 产出 *grpc.Server
      - newApp(logger, hs, gs) 是清单最后一项,收齐所有产出 → *kratos.App
      - 返回类型声明 (*kratos.App, func(), error) 和 newApp 的产出匹配 → wire 装配成功
      - 任何一环找不到(比如你删了 NewHTTPServer 或写错参数类型),wire 直接报错 —— 这就是 Issue 1 检查点第 2 条的玩法
4. newApp 必须在 main 包里 —— wire 生成的代码会直接调用它,跨包调用未导出函数会编译失败。


## 5. 字符串无法转换成结构体问题
问题
```bash
$ make run-commerce
go run ./services/commerce/cmd/commerce -conf services/commerce/configs
DEBUG msg=config loaded: config.yaml format: yaml
INFO msg=watcher's ctx cancel : context canceled
panic: json: cannot unmarshal string into Go struct field GRPC.Server.GRPC.Timeout of type time.Duration

goroutine 1 [running]:
main.main()
        C:/Users/peropero/GolandProjects/kratos-payment-lab/services/commerce/cmd/commerce/main.go:45 +0x39a
exit status 2
make: *** [Makefile:33: run-commerce] Error 1
```

原因

Kratos 的 config 包(yaml → JSON 转换后解析)不支持把 "10s" 字符串直接反序列化到 time.Duration 字段——JSON 标准库没有为 time.Duration 提供字符串解析。

解决方案(每个服务 3 处)

```go
   //config.go — 新增 Duration 自定义类型:
package config

import (
   "encoding/json"
   "time"
)

type Duration time.Duration

func (d *Duration) UnmarshalJSON(b []byte) error {
   var v string
   if err := json.Unmarshal(b, &v); err != nil {
      return err
   }
   du, err := time.ParseDuration(v)
   if err != nil {
      return err
   }
   *d = Duration(du)
   return nil

}
//HTTP.Timeout / GRPC.Timeout 字段类型改为 Duration。

//http.go / grpc.go — 使用处转换回 time.Duration:
//if c.HTTP.Timeout > 0 {
//opts = append(opts, http.Timeout(c.HTTP.Timeout))
//}
```
